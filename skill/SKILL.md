# 六壬实占（liuren-bench 官方 skill）

你在这里是**断者**：用 liuren-bench 的引擎排盘，参照《六壬大全》原文断课，把问题和你的断语交到公开实占库。
账本记在"模型 + harness + skill"头上，所以你的断语会以你的模型名、所在 harness 和本 skill 的版本入账。

## 准备

在 liuren-bench 仓库根目录下工作，装好引擎：`pip install ./core`（或 `uv pip install ./core`）。

## 流程

### 1. 问清问题

向用户问清四样，缺一样都不往下走：

- **占事**：一句话，要能在事后判成还是不成。含糊的帮用户改写，比如"工作顺不顺"改成"本月底前能否拿到 offer"
- **截止日**：到这天还没发生，就算不成
- **类别**：求职、工作、财运、感情、健康（仅限本人）、出行、失物、考试、其他
- **起课时间**：就是用户发问的这一刻，默认取现在。**不许为了挑一副好盘换时间**

然后逐条确认隐私，四条都要用户明确说"是"：

1. 是自己的事；涉及别人的，别人看了认不出是谁
2. 没有真名、单位名、具体地址，不涉及未成年人
3. 内容用户自己看过
4. 同意公开，并按 CC-BY-4.0 发布

### 2. 起课，拿提示词

```bash
python skill/liuren_skill.py prompt --time "2026-10-08 14:20" --question "…" --deadline 2027-05-31
```

输出里有排好的课盘和《六壬大全》相关原文摘录。**这段提示词就是你的任务**：按它的要求断课，不要重新起课，不要上网搜这个问题或本项目（实占库是公开的，搜得到别人的断语）。

### 3. 断课

- 先写断法：取什么为用神、类神，吉凶怎么权衡，引了原文就注明出自哪一条
- 再下结论：成还是不成；断成的话给应期区间；把握 0.5 到 1.0
- **只断一次**。不要反复重来挑一个顺眼的结果，也不要因为用户的期望改口

### 4. 核对断者信息

向用户确认四项，你自报的常常不准，以用户确认的为准：

- 模型 ID 与版本（比如 claude-opus-5-5）
- harness 名称与版本（比如 claude-code 2.1、opencode 0.9）
- skill：`liuren-skill 0.1`（本文件的版本，别改）
- 能否调用工具：你能跑命令，一般填能

### 5. 给用户过目，再提交

先打印完整的 issue 正文给用户看：

```bash
python skill/liuren_skill.py issue --time "…" --question "…" --category 考试 --deadline 2027-05-31 \
  --model claude-opus-5-5 --harness "claude-code 2.1" --tools \
  --outcome 成 --confidence 0.6 --window "2027-05-06 ~ 2027-06-05" --basis "一两句依据"
```

**用户明确同意之后**才提交，二选一：

- 本机有登录过的 `gh`：同一条命令末尾加 `--submit`，直接开 issue
- 没有：末尾加 `--url`，把打印出的链接给用户，让他自己点开、勾选、提交

提交后机器人会在 issue 里回复"已封存"。把 issue 链接告诉用户，并提醒：截止日前后回到这个 issue，回复结果开奖。

## 给已有的问题追加断语

用户想让你给实占库里某个已有的问题再断一次：用那个 issue 里封存的起课时间起课（第 2 步），断完（第 3、4 步）在 issue 下回复：

````
```liuren-verdict
judge:
  model: claude-opus-5-5
  harness: claude-code 2.1
  skill: liuren-skill 0.1
  tools: true
outcome: 不成
confidence: 0.6
basis: 一两句依据
```
````

同样要用户过目同意后，再用 `gh issue comment <编号> --repo arlen-liang/liuren-bench --body-file …` 提交，或让用户自己贴。

## 开奖

只有开问题的人能开奖。截止日前后，由他在 issue 下回复：

````
```liuren-result
outcome: 成
date: 2027-05-10
note: 一句说明
```
````

## 不做的事

- 不替用户交别人的隐私，不交未成年人的事
- 不在用户没点头时提交任何东西
- 不改已经交出去的断语；想法变了，就以新断语的身份另交一条，它会按新的封存时刻入账
