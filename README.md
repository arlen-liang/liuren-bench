# liuren-bench

**中文** | [English](README.en.md)

liuren-bench 是一个拿大六壬考大模型的项目：给 AI 一个时刻，让它排出天地盘、四课、三传，再跟程序排的盘逐项对答案。顺带，它也是一本公开的算命记账本。

目前是 pre-alpha：起课引擎的草案刚写出来（`core/`），能排盘、能过 720 课自洽检验，但规则还没拿古籍对过，见[规则待核清单](docs/rules.md)。评测部分还没开工。

## 为什么拿六壬考 AI

大六壬，即以月将加占时起天地盘、由日干支取四课、再依九宗门发出三传的一门古老占法，与奇门遁甲、太乙神数并称"三式"。

先别管它准不准。单看起课这一步，就是一条相当长的规则链：换算历法、推干支、查表，最后按一串有先后顺序的规则取出三传。一步错，后面全错，而且能精确定位是在哪一步翻的车。

同一时刻、同一流派，谁排出来的盘都一样，所以有标准答案。时刻随便取，题目无限供应，想背题都没门。规则和术语又全是中文加文言，拿来考中文模型正合适。

## 四种玩法

### 起课轨：会不会排盘

给时刻，让模型排天地盘、四课、三传、天将。程序出答案，逐项判分，能看出它是换将换错了、贵人起错了，还是取传规则用错了。

分闭卷和开卷。闭卷只给时刻，看它自己会不会；开卷把起课规则全文甩给它，看它能不能照着做。

### 古文轨：读不读得懂原典

拿《课经》《毕法赋》出阅读题，答案对着原文判。

### 断语轨：能不能复现古人的判断

从古籍里挑课例，把原书的断语遮住，让模型自己断，再跟原书对照。这里测的是"像不像古人"，不是"准不准"，古人自己准不准是另一回事。

### 实占库：先下注，后开奖

这是最好玩的一块。任何人都可以把自己起的课交上来，分两步：

1. 起课时交一次：课盘、占的什么事、你的断语
2. 应期过了再交一次：实际结果如何

两次之间断语不许改，改了 CI 直接打回。结果出来才想起补交的也收，但会打上"马后炮"标签，不进统计。

同一课可以挂好几家的断语，人可以断，模型也可以断，一起封存，一起开奖。攒下来，每位断课者都有一本公开的账：断了几次，中了几次，还有几次没回来填坑。

对模型来说，这也是最干净的一种考法。断语封存的时候结果还没发生，哪家模型都不可能提前背过答案。

至于六壬到底灵不灵，本项目不下结论，只记账。

## 仓库结构

```
core/           起课引擎：时间 → 课盘（MIT）
bench/          出题、判分、榜单（MIT）
cases/
  classical/    古籍课例：课盘 + 原文断语 + 出处（CC-BY-4.0）
  live/         实占库：一课一个文件，先下注后开奖（CC-BY-4.0）
docs/           方法说明：720 课、判分口径、流派开关
```

## 路线图

M1 起课引擎 → 实占库开张 → M2 起课轨 v0 → M3 古籍课例与古文轨 → M4 断语轨，当前处于 M1。

实占库排得这么靠前，是因为开奖要等。一课的应期动辄几个月，早开张早攒账。详见 [ROADMAP.md](ROADMAP.md)。

## 怎么参与

作者本人不会断课（对，你没看错）。引擎排得对不对，只能拿古籍里现成的课盘来校。所以非常欢迎：

- 古籍里带完整课盘的课例，注明书名、版本、卷次
- 各派在哪条规则上打架，各自出自哪本书
- 你自己的实占，先下注，后开奖
- 捉虫

怎么交、有什么规矩，见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 丑话说在前头

最大的坑：所谓"标准答案"只是某一流派下的答案。默认按《大六壬指南》起课，已知的分歧做成开关；要是有哪条分歧没被发现，评测就会把人家流派的正确答案判成错。这个坑得靠懂行的人一起填。

古籍课例天生有偏差，古人爱记准的，不准的多半没留下来，名课还很可能早就被模型"见过"。实占库正好补这个缺，但它也有自己的毛病：愿意来交的人，多半本来就对六壬有几分信，样本谈不上有代表性。

最后，本项目一人业余维护，更新随缘。
