# liuren-bench

**中文** | [English](README.en.md)

liuren-bench 是一个拿大六壬考 AI 的项目：让 AI 起课、断课，先下注，等结果出来再开奖，一笔一笔记在公开的账本上。考的不只是模型，还有装着模型的那套 harness。

目前是 pre-alpha：起课引擎（`core/`）能从公历时间直接起课，能过 720 课自洽检验，九宗门口诀已与《六壬大全》逐条对过，见[规则核对清单](docs/rules.md)。实占库和官方 skill 还没开张。

## 为什么拿六壬考 AI

大六壬，即以月将加占时起天地盘、由日干支取四课、再依九宗门发出三传的一门古老占法，与奇门遁甲、太乙神数并称"三式"。

它正好一半"定"、一半"不定"。起课排盘是纯计算，同一时刻、同一流派，谁排出来的盘都一样，有标准答案；断课则全凭取象、权衡，古人叫"神断"，没有公式。前一半考的是长链规则执行，后一半考的是在一堆互相打架的信号里拿主意。规则和术语又全是中文加文言，拿来考中文模型正合适。

## 考的是谁：断者

断者，即给出断语的一方：可以是一个人，也可以是一套"模型 + harness + skill"。

同一个模型，放在网页聊天框里裸考，和装进 Claude Code、Codex 这类能跑代码、能查资料的 harness 里，断出来的东西可能完全两样。所以本项目不把账记在"某某模型"头上，而是记在断者头上。每条 AI 断语都要报清楚：

- 模型 ID 与版本
- harness 名称与版本
- 用的 skill 或提示词及其版本
- 能不能调用工具

## 玩法

### 实占库：先下注，后开奖

这是主打。任何人都可以把一个真实的问题交上来，每个问题开一个 issue：

1. 下注：写明起课时间、占的什么事、截止日，附上断语
2. 开奖：截止日前后回到这个 issue，回复实际结果

issue 一开，机器人就回复一条"已封存"：排好的课盘、引擎版本、断语原文、封存时刻，全钉在 issue 里。之后谁改了原帖、删了回复，都以封存那一条为准。结果出来才想起补交的也收，但会打上"马后炮"标签，不进统计。

**自己不会断课也完全没关系。** 你负责提问、下注、回来开奖，断课交给 AI 就行。同一个问题可以让好几家 AI 各断一次，在同一个 issue 下回复，一起封存，一起开奖，天然就是一场擂台。

攒下来，每位断者都有一本公开的账：断了几次，中了几次，还有几次没回来填坑。

有一点要说在前面：这本账里 AI 的断语都是用户自己交的，用的哪个模型全凭自报，断了十次挑一次交也拦不住。所以它适合看个热闹、看看大家都在用什么模型，不适合当严格的模型评测。严格的评测看后面的起课轨和断语轨，那两轨由评测脚本统一出题、统一调用模型。

至于六壬到底灵不灵，本项目不下结论，只记账。

### 网页版和官方 skill：拉下来就能用

网页版给用网页聊天的人：填上时间和问题，页面排好盘、生成一段提示词，粘进你常用的 AI，把回答粘回来，页面生成一个预填好的 issue 链接，点提交就行。

官方 skill 给用 Claude Code、opencode 这类 agent 的人，装进去就能起课、断课、交卷：

1. 用 `core/` 引擎排盘，"定"的部分不让模型瞎猜
2. 按一份以《六壬大全》为据的断法，引导模型给出能判对错的断语：成不成、应期在哪个区间、有几成把握
3. 填好断者信息（模型、harness、skill 版本），请你确认
4. 你看一眼、点头之后才提交：有 `gh` 的直接开 issue，没有的生成预填链接

两条路都要有 GitHub 账号，提交走的是你自己的账号。本项目不设公开 API，不经手任何人的数据。

### 起课轨：会不会排盘

给时刻，让 AI 排天地盘、四课、三传、天将。程序出答案，逐项判分，能看出它是换将换错了、贵人起错了，还是取传规则用错了。

分两个榜：

- 裸考：不许用工具，只靠模型自己
- agent 考：允许写代码、查资料，但不许调用现成的排盘库（包括本项目的 `core/`）。会不会想到"这题该算不该猜"，本身就是在考 harness

### 古文轨：读不读得懂原典

拿《课经》《毕法赋》出阅读题，答案对着原文判。

### 断语轨：能不能复现古人的判断

从古籍里挑课例，把原书的断语遮住，让 AI 自己断，再跟原书对照。这里测的是"像不像古人"，不是"准不准"，古人自己准不准是另一回事。

## 仓库结构

```
core/           起课引擎：时间 → 课盘（MIT）
bot/            实占库机器人：封存、导出（MIT）
web/            网页版（MIT）
skill/          提示词与官方 skill（MIT，skill 施工中）
bench/          出题、判分、榜单（MIT，规划中）
cases/
  classical/    古籍课例：课盘 + 原文断语 + 出处（CC-BY-4.0）
docs/           规则核对清单、数据格式
```

实占库的原件就是带 `live-case` 标签的 issue。数据集每天导出一次，放在 `data` 分支（CC-BY-4.0），这个分支不留历史：删掉一个 issue，下次导出它就没了。

## 路线图

M1 起课引擎 → M2 实占库与官方 skill → M3 起课轨 → M4 古籍课例与古文轨 → M5 断语轨。M1 已完成，当前处于 M2。

实占库和 skill 排在评测前面，一是好玩的都在这儿，二是开奖要等，一课的应期动辄几个月，早开张早攒账。详见 [ROADMAP.md](ROADMAP.md)。

## 怎么参与

- 用网页版或官方 skill 让你的 AI 断一课，下注，回来开奖。不会断课的人最欢迎
- 古籍里带完整课盘的课例，注明书名、版本、卷次
- 各派在哪条规则上打架，各自出自哪本书
- 捉虫

作者本人不会断课（对，你没看错），引擎排得对不对，只能拿古籍里现成的课盘来校，所以懂行的人尤其欢迎。怎么交、有什么规矩，见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 丑话说在前头

最大的坑：所谓"标准答案"只是某一流派下的答案。引擎以《六壬大全》为准（能查到全文、能逐条对账），已知的分歧做成开关；要是有哪条分歧没被发现，评测就会把人家流派的正确答案判成错。这个坑得靠懂行的人一起填。

断者信息全靠自报，本项目没法验证谁真用了哪个模型。统计按自报分组，也会标明是自报。开奖结果同样全靠提问人自报，回填率能看出谁只报喜不报忧，看不出谁报了假。

要交实占得有 GitHub 账号，而 GitHub 在国内时好时坏。这和"欢迎普通人来玩"是拧着的，眼下没有好办法，先认这个门槛。

古籍课例天生有偏差，古人爱记准的，不准的多半没留下来，名课还很可能早就被模型"见过"。实占库正好补这个缺，但它也有自己的毛病：愿意来交的人，多半本来就对六壬有几分信，样本谈不上有代表性。

最后，本项目一人业余维护，更新随缘。
